# Maintained Fleet host release

Fleet's current invitation and HFD1 DeviceLogin protocol uses fixed dashboard paths and its existing dashboard session/WebSocket-ticket authentication. Hermes dashboard plugins expose namespaced paths; the API server key grants broad agent access. Neither is a replacement for the existing phone protocol. Never provide `API_SERVER_KEY` to Fleet.

This repository therefore maintains a narrow, offline source overlay and a separate owner-control plugin. The installer, manifest, rollback state and plugin remain outside the Hermes source checkout. The release contains the seven locally authored pairing/Telegram safeguards plus the reviewed status-only QR safety change. It is not a stock Hermes release. See [the installer procedure](../host-tools/README.md) for independently pinned checksums, supported source fingerprints, isolated staging, canonical validation, explicit source application, and rollback.

## Compatibility and update behavior

The installer supports reviewed file preimages from the recorded baseline and a narrow upgrade from the prior ECD overlay. It never guesses compatibility from version names or commit ancestry. Dirty source is a blocker; preserve the full working tree, including untracked files, and reconcile each change in an isolated candidate before authorizing installation. A newer source whose relevant files differ requires a reviewed release adaptation and tests. Do not force a patch through conflicts.

A stock update does not install this Fleet capability. It can remove an overlay while leaving the external installer and plugin intact. Before issuance and after every Hermes update, the readiness helper verifies the source and PM runtime against the pinned release. Drift blocks issuance. Stage and validate reconciliation against the exact updated source before applying it; do not modify Hermes's updater or replace its dependency/config migrations. This release detects missing capabilities and supports controlled reconciliation; it does not automatically update arbitrary future Hermes versions.

Source application leaves the checkout with reviewed tracked changes and an external transaction receipt. It does not refresh the PM runtime, rewrite profile settings, enable a plugin, change a service, or restart a daemon. Those actions require a separate reviewed activation plan for the exact host. Snapshot profile/config/service definitions before any authorized activation. Use Hermes's supported PM/plugin procedures; never write into its runtime or use raw pip/uv. A launcher permission failure must be diagnosed and approved separately, without chmod or lock bypass.

## Profile and owner prerequisites

The complete owner-control plugin is distributed in a pinned local Git bundle and installed through Hermes's supported local Git-source plugin path, initially disabled. There is no invented download URL and no GitHub publication requirement. Plugin installation, enabling and service restart require approval; read-only planning and disposable candidates do not activate a host.

The selected effective Telegram platform settings must contain a nonempty list of explicit numeric `fleet_pairing_owner_user_ids`. Its `fleet_pairing_host` mapping selects `hermes_home`, `source`, `runtime_source`, `manifest`, `trusted_manifest_sha256`, `origin`, and `approval`. Use the profile's approved round-trip config writer; do not copy credentials between profiles. The active home, effective configuration and adapter must agree. Missing or ambiguous scope fails closed.

The native adapter handler requires a supported plugin execution mode. A managed plugin-isolation policy that refuses live adapter registration is a blocker, not permission to weaken that policy. Verify this during the separately authorized target inspection.

The readiness command uses the selected Hermes runtime interpreter and its read-only configuration loader. When running it outside Hermes, use that runtime's workspace on Python's import path and the explicit selected Hermes home. A system Python without the matching runtime/config loader reports a blocker instead of guessing. Pass exact source/runtime/home selections, origin and independently trusted manifest digest as documented by `readiness.py --help`. `--probe-https` is optional and performs only a bounded, redirect-refusing GET to `/api/auth/providers`, using trusted TLS and no credentials. It proves host route/trust only, not that a particular daemon loaded the current code or that the phone can reach it.

Owner observations must separately prove the running service's code/profile/forwarding, phone HTTPS reachability and iOS trust, and private interactive local display. A private tailnet hostname works when the phone belongs to the network, resolves/reaches it and trusts its certificate. Public internet exposure and Funnel are not required. A bare IP, single-label name or untrusted certificate is unsupported.

Only after those real observations and explicit approval may `record_observations.py` record a new protected receipt outside the source and Hermes home. It requires all three observation flags, checks the release/source/runtime/effective origin and trusted host route, binds the receipt to the exact home/runtime/origin/config/manifest, and expires it after ten minutes. Do not set an observation flag based on a fixture, an assumption or a readiness report alone. This task does not create that live approval receipt.

`/fleetstatus` verifies a real private numeric-owner event plus Hermes's ordinary gateway access policy and returns safe status without creating invitations or stores. `/fleetqr` is the explicit issuance request. It additionally requires all readiness gates, records a durable atomic request receipt, then captures the real issuer's output in memory and renders its QR via standard input. Neither the link nor its secret is returned in Telegram. Groups, forwarded requests, nonowners, denied ordinary access, wrong profiles and unverified prerequisites cannot mint. Replay storage survives restart, has a fixed capacity and refuses when unavailable/full; never silently reset it.

The first display implementation supports a verified macOS GUI session with qrencode and Quick Look. A successful process launch does not prove private visibility. The owner must have observed it separately before issuance. The bearer PNG is mode 0600 under a mode 0700 temporary directory, removed on close, normal error, timeout or handled termination. Abrupt machine loss/SIGKILL cannot promise immediate deletion; preserve evidence and remove only identified expired helper files under an approved recovery procedure. No credential-bearing viewer arguments, logs or Telegram attachments are used.

## Safe fresh-onboarding acceptance

Use a fresh, task-owned simulator for fixture acceptance. Never clear the existing physical DEV app, production app, saved gateways, Keychain, TLS pins or cache to force first run. If the phone already has saved gateways, verify their continuity and use the existing add-server QR path with a separately approved real host. A physical first-run gate requires an explicitly authorized separate clean DEV test namespace or a genuinely fresh device; this task does not create either.

After host activation and phone delivery are separately authorized and verified, Tony performs the physical scan and explicit **Connect this phone**. First inspect the host's current pending invitations/device list under owner authority to avoid orphaned prior attempts. Record host identity, broad `fleet:operator` disclosure, successful authenticated server entry, relaunch/reconnect and existing-data continuity without logging secrets. Revocation or removal testing must be scoped to the newly created test device and explicitly approved. Do not revoke another phone, issue ongoing credentials silently, or reset an existing gateway.

Lost responses or process death between server redemption and secure phone saving can still leave an orphaned device under the existing invitation protocol. Inspect/revoke only that attempt under owner authority before issuing again. Fixtures do not prove real Telegram authority, Mini activation, private host display, physical camera, phone TLS trust or live authenticated access.
